# StudyPilot：基于 RAG 的个性化课程学习助手

- 日期：2026-08-10
- 状态：已完成设计，等待用户书面审阅
- 目标：作为 AI/大模型应用实习作品，在约 5 周、每周至少 10 小时的投入下完成可部署版本
- 预算：模型 API 与必要部署费用合计控制在 50–100 元以内

## 1. 项目定位

StudyPilot 面向大学生，将课程 PDF 转化为可检索、可问答、可练习、可追踪的学习内容。项目的核心价值不是简单调用大模型，而是完成一条可解释、可评测的学习闭环：

1. 用户创建课程并上传 PDF。
2. 系统解析资料、保留页码并建立向量索引。
3. 用户根据资料提问，系统返回带原文引用的回答。
4. 系统根据指定资料生成测验并批改答案。
5. 错题被归纳为薄弱知识点，展示在学习看板中。

该项目用于展示 Python、FastAPI、React、PostgreSQL、向量检索、模型 API、测试、部署与技术文档能力。

## 2. 范围

### 2.1 第一版功能

- 注册、登录与 JWT 身份验证
- 创建、查看和删除课程
- 上传、查看、重新处理和删除文字版 PDF
- 显示文档解析状态与失败原因
- 基于课程资料进行引用式问答
- 查看回答引用的文档、页码和原文片段
- 根据指定资料生成选择题与简答题
- 提交答案、查看分数与解析
- 保存错题并统计薄弱知识点
- 查看课程正确率、练习数量和薄弱主题
- 提供线上演示、演示账号、API 文档、架构图和完整 README

### 2.2 明确不做

第一版不实现语音交互、OCR、图片理解、知识图谱、多 Agent、多人协作、社交功能、原生移动端、付费系统和模型训练。这些功能不属于实习作品的最小闭环。

## 3. 用户流程

1. 用户注册或登录。
2. 用户在课程列表创建课程，例如“计算机网络”。
3. 用户进入课程工作台并上传 PDF。
4. 后端保存文件，创建处理任务，并将文档状态设为 `processing`。
5. 后端按页解析、切分文本、批量生成向量并保存；成功后状态变为 `ready`，失败则变为 `failed` 并允许重试。
6. 用户在问答页输入问题。后端检索课程内相关片段，生成回答和引用并保存对话。
7. 用户选择一份或多份已处理资料生成测验。
8. 用户作答后得到分数、逐题解析和知识点反馈。
9. 系统更新错题记录和薄弱知识点，用户可在看板中查看学习概况。

## 4. 系统架构

系统由四层组成：

- React 前端：课程、资料、问答、测验、错题与看板界面。
- FastAPI 后端：身份验证、业务接口、文档处理、RAG 编排、出题、批改和统计。
- PostgreSQL + pgvector：同时保存关系数据、文档片段与向量。
- 外部服务：Supabase Storage 保存原始 PDF；阿里云百炼提供对话与 Embedding API。

前端只访问 FastAPI，不直接持有模型 API Key 或数据库凭据。后端通过环境变量配置数据库、对象存储、JWT 和模型服务。

## 5. 后端模块

### 5.1 用户模块

- 注册时校验邮箱格式和密码强度，并保存密码哈希。
- 登录成功后签发短期 JWT。
- 所有课程资源查询必须包含当前用户条件，避免越权访问。

### 5.2 课程与资料模块

- 管理课程的创建、列表、详情和删除。
- PDF 限制为 20 MB、300 页以内，只接受声明类型与文件签名均符合 PDF 的文件。
- 使用 PyMuPDF 按页提取文字；无有效文本的扫描件返回“不支持扫描版 PDF”。
- 文件存入私有对象存储，数据库只保存对象路径和元数据。
- 上传接口使用 FastAPI `BackgroundTasks` 启动文档处理并立即返回文档 ID。处理开始时间写入数据库；服务启动时将超过 15 分钟仍为 `processing` 的任务标记为 `failed`，用户可手动重试。
- 文档处理具有幂等性：重新处理前删除该文档旧片段和旧向量，避免重复数据。

### 5.3 RAG 问答模块

- 在单页范围内按约 700 Token 切分，重叠约 100 Token，确保引用页码准确。
- 使用 `text-embedding-v4` 生成 1024 维向量。
- 问题向量化后，以余弦距离在指定课程内检索前 5 个片段。
- 低于相关度阈值时返回“资料中没有足够信息”，不调用回答生成或要求模型拒答。
- 提示词将资料片段标记为不可信数据，禁止执行资料中的指令。
- 回答响应包含正文、引用编号、文档名、页码和原文摘要。
- 模型提供者通过统一接口封装，默认使用阿里云百炼 `qwen-plus`，允许通过配置替换兼容服务。

### 5.4 测验模块

- 模型输出固定 JSON 结构：题型、题干、选项、标准答案、知识点、难度和解析。
- 使用 Pydantic 校验输出；首次格式错误时携带校验错误重试一次，仍失败则返回可重试错误。
- 选择题由程序判分。
- 简答题由模型依据标准答案和评分要点给出 0–10 分、反馈与缺失要点。
- 生成题目时保存来源文档和引用页码，方便用户核对。

### 5.5 学习分析模块

- 按课程统计作答次数、题目数量、平均正确率和最近练习。
- 对每道错题的知识点累计错误次数，并结合总作答次数计算薄弱度。
- 第一版只展示规则统计，不使用大模型生成复杂学习路径。

## 6. 数据模型

核心表及关系如下：

- `users`：用户账号与密码哈希。
- `courses`：属于某个用户的课程。
- `documents`：属于课程的 PDF、对象路径、页数和处理状态。
- `document_chunks`：属于文档的文本片段、页码、Token 数和 `vector(1024)`。
- `conversations`：属于课程和用户的会话。
- `messages`：会话消息、回答正文与模型信息。
- `message_citations`：回答引用的片段、页码和展示摘要。
- `quizzes`：测验标题、课程、生成状态和来源范围。
- `questions`：题型、题干、选项、答案、解析、知识点、难度与来源。
- `attempts`：用户的一次测验提交、总分和时间。
- `answers`：逐题答案、得分、反馈和是否正确。

薄弱知识点不单独保存为模型事实，而是从 `questions` 与 `answers` 聚合得到，避免重复状态不一致。必要时可增加可重建的统计缓存。

## 7. API 边界

主要接口按资源分组：

- `/auth/register`、`/auth/login`、`/auth/me`
- `/courses`、`/courses/{course_id}`
- `/courses/{course_id}/documents`
- `/documents/{document_id}`、`/documents/{document_id}/retry`
- `/courses/{course_id}/conversations`
- `/conversations/{conversation_id}/messages`
- `/courses/{course_id}/quizzes`
- `/quizzes/{quiz_id}`、`/quizzes/{quiz_id}/submit`
- `/courses/{course_id}/analytics`

成功响应使用明确的 Pydantic schema；错误响应统一包含错误代码、用户可读消息和请求 ID。前端不依赖模型服务的原始响应格式。

## 8. 前端设计

### 8.1 页面

- 登录与注册页
- 课程列表页
- 课程工作台
- 课程资料页
- 引用式问答页
- 测验生成、答题与结果页
- 错题页
- 学习分析页

### 8.2 课程工作台布局

顶部显示产品名、课程路径与用户菜单。左侧导航在资料问答、课程资料、智能测验、错题本和学习分析之间切换。问答页面中间为聊天区，右侧显示课程资料、快捷出题入口和学习概况。点击引用时展示文档名、页码与原文摘要。

### 8.3 状态反馈

- 上传过程中显示文件进度。
- 文档状态包含 `uploaded`、`processing`、`ready`、`failed`。
- 问答与出题展示加载状态，禁止重复提交。
- 所有失败状态提供可操作提示；文档处理失败提供“重新处理”。

## 9. 异常、安全与成本控制

- API Key、数据库密码和 JWT Secret 只存在于后端环境变量。
- 密码使用可靠哈希算法，JWT 设置过期时间。
- CORS 只允许配置的前端域名。
- 每次资源访问检查所属用户。
- 文件名由后端重新生成，不使用用户输入拼接路径。
- 上传接口限制类型、大小和页数。
- 模型与 Embedding 调用设置超时；网络错误指数退避重试最多两次。
- 每个用户设置每日问答、出题和上传配额，防止演示账号耗尽预算。
- 日志记录请求 ID、耗时、模型名、Token 用量和错误类型，但不记录密码、Token、完整 PDF 或 API Key。
- 删除文档时删除对象存储文件、片段和向量；删除课程时级联清理所属数据。

## 10. 测试与 RAG 评测

### 10.1 自动化测试

- 后端使用 pytest 测试切分、检索、鉴权、判分和统计逻辑。
- 使用 FastAPI 测试客户端覆盖注册、登录、课程、文档、问答、测验和分析接口。
- 模型与对象存储在测试中使用替身，稳定验证超时、错误 JSON、重试与失败状态。
- 前端使用 Vitest 测试关键组件与状态逻辑。
- 使用 Playwright 覆盖一条核心冒烟流程：登录、进入课程、提问、查看引用、完成测验。
- GitHub Actions 在每次推送和拉取请求时运行后端测试、前端测试与生产构建。

### 10.2 RAG 质量评测

仓库内提供一份允许再分发的公开课程资料和至少 20 个评测问题，其中包含可回答问题与资料外问题。每个可回答问题标注正确页码，资料外问题标注应拒答。评测脚本输出：

- `retrieval_hit@5`：正确页是否出现在前 5 个检索片段中。
- 引用页码准确率：最终回答引用是否包含正确页。
- 拒答准确率：资料外问题是否被正确拒答。
- 平均接口耗时与单次调用 Token 用量。

README 展示固定模型和固定数据集下的评测结果，并记录评测日期与配置，避免只展示主观案例。

## 11. 部署

- React 前端部署到 Vercel Hobby，仅作为个人非商业作品展示。
- FastAPI 部署为 Render Web Service；免费实例休眠导致的首次冷启动在 README 与界面中提示。
- PostgreSQL、pgvector 与私有 PDF 存储使用 Supabase 免费项目。
- 阿里云百炼通过 OpenAI 兼容接口调用，默认使用 `qwen-plus` 和 `text-embedding-v4`。
- 本地开发提供 Docker Compose 启动 PostgreSQL + pgvector；前后端分别支持热更新。
- 提供 `.env.example`、数据库迁移、演示数据初始化和部署说明。

Render 本地文件系统是临时的，因此 PDF 不保存在后端磁盘。Supabase 免费项目可能因长期无活动暂停，适合作品演示而非生产服务。

## 12. 验收标准

完成版本必须同时满足：

1. 用户能注册、登录、创建课程并上传合规 PDF。
2. 文档处理状态可见，失败可重试，扫描版有明确提示。
3. 问答返回受资料支持的答案、文档名、页码和原文摘要。
4. 资料没有答案时系统能够拒答。
5. 用户能生成并完成选择题和简答题测验。
6. 系统保存错题并展示课程正确率和薄弱知识点。
7. 两个测试用户之间无法访问对方资源。
8. 后端测试、前端测试和生产构建在 CI 中通过。
9. RAG 评测脚本能够重复运行并输出四项约定指标。
10. 线上演示、演示账号、OpenAPI 文档和 README 可供招聘方访问。

## 13. 五周交付边界

- 第 1 周：Python、HTTP、Git 基础与前后端骨架；完成用户和课程模块。
- 第 2 周：PDF 上传、解析、切分、数据库与向量写入。
- 第 3 周：引用式 RAG 问答与聊天界面。
- 第 4 周：测验、批改、错题和学习分析。
- 第 5 周：自动化测试、RAG 评测、部署、截图、README 与简历描述。

如果进度落后，优先保留资料上传、引用式问答、选择题测验和 RAG 评测；简答题批改、错题筛选和看板图表可降级，但不会以增加多 Agent 等新功能替代核心质量。
